## Universal archive inspection and dependency-free run

The archive was built from an explicit allowlist with fixed timestamps, sorted paths, normalized permissions, and no symlink traversal. Inspection confirmed:

- one `regulatory-harvest/` archive root;
- `SKILL.md`, both deterministic engines, runner, templates, references, license, notices, README, and package metadata are present; and
- Git state, worktrees, tests, internal plans, verification records, caches, generated matters, prior distributions, and private records are absent.

The exact archive was extracted into new temporary directories and invoked with `python -I -S`, `PYTHONNOUSERSITE=1`, and `PIP_NO_INDEX=1`. The extracted runner completed `prepare` and `finalize` in both `provided-only` and `web` modes without importing the development checkout, creating a virtual environment, installing a package, or accessing a package index. For the offline web-mode case, the host supplied a local capture of retrieved public-source text as the skill instructs.

Both extracted flows produced a substantive finding, an exact resolved citation, a sealed bundle, `valid: true`, and `status: completed`. The full package validator independently accepted each portable-engine bundle. Adversarial tests additionally confirm that the portable engine rejects private-network URLs, refuses to guess among ambiguous quote occurrences, and blocks symlinked managed paths.

## Codex product acceptance

The exact final ZIP was installed at `$HOME/.agents/skills/regulatory-harvest`. All 76 packaged files match the ZIP entry-for-entry and byte-for-byte by SHA-256. The installed folder passed both the Codex quick validator and the shared Agent Skills reference validator.

The current installed candidate was exercised in both modes:

- In `provided-only`, Codex used only a two-section synthetic fixture, produced one substantive finding with one exact citation, preserved two closed-universe gaps, and returned `valid: true`, `status: completed`, zero validation issues, and zero blocking review items.
- In `web`, Codex researched the FTC notification rule in 16 CFR 314.4(j) using official U.S. government sources. The eCFR page returned an automated-access challenge, so Codex preserved an exact local capture of the FederalRegister.gov final-rule rendition and recorded the eCFR, official-PDF, host-capture, currentness, and entity-applicability limitations as explicit gaps. The engine produced one finding, four claims, four exact citations, four gaps, one non-blocking lexical warning, no review items, a sealed bundle, `valid: true`, and `status: completed`. The standalone package validator also accepted the bundle.

These checks confirm Codex discovery, activation, source-mode control, host research handoff, installed-script execution, exact-quote resolution, warning preservation, sealing, and delivery behavior for the final candidate.

## Claude product acceptance

An authenticated Claude Customize session accepted, enabled, and invoked the 76-file private skill. Two fresh chats were used so the tests did not inherit the earlier failed attempt:

- In `provided-only`, Claude loaded `regulatory-harvest`, ran the bundled dependency-free engine in its no-network code sandbox, produced downloadable report, bundle, and receipt artifacts, and reported `valid: true`, `status: completed`, zero validation issues, and zero blocking review items.
- In `web`, Claude used its host web-research capability to retrieve official eCFR and Federal Register sources, saved exact source text locally for the code sandbox, ran the deterministic engine, and produced the same three downloadable artifacts. The receipt reported `valid: true`, `status: completed`, zero blocking review items, and two non-blocking lexical warnings. Claude kept the official-edition, capture-path, currentness, drafting-slip, and entity-applicability limitations visible.

The first authenticated Claude attempt was also valuable adverse evidence: the earlier runner tried to install missing `pydantic` and `httpx` into a no-network sandbox and failed closed with `RUNTIME_SETUP_FAILED`. That product failure directly caused the dependency-free standard-library engine and its adversarial tests.

After the successful product scenarios, one stale sentence in `references/security-and-privacy.md` was found describing the removed pip/virtual-environment behavior. The sentence was corrected, the final ZIP was rebuilt and privately replaced in Claude, and Claude's file viewer displayed the corrected no-install runtime boundary. The executable files were unchanged by that final documentation-only synchronization, so the two full scenarios were not repeated afterward.
